Coding agents like Claude Code or Codex can now build real features on their own, but they have a catch: every new session starts from zero. The agent forgets yesterday's decisions, the reasons behind them, and the exact next step, so you end up re-explaining the project every time. The fix is giving the agent a memory. After two weeks on a real project (SpaceMaker, 186 commits), I learned the hard part is not storing things, it is that "memory" is really three different things that age differently: state (where we are right now), facts (decisions that stay true), and rules (what the agent must always follow). Mix them and it breaks: a "next step" stored as a fact is false tomorrow, and nothing says so.

So I split them. A markdown memory bank in git holds the state, and it follows the branch and shows up in PR diffs. jevmem, a small typed note store, holds one dated fact per note and recalls only the few that matter, and it tells the agent when it doesn't know. AGENTS.md holds the rules. The store never calls a generative LLM: a small, fast model answers typed questions like "is this a status note?", and the big model only writes and answers. On my test sets, recall of the right note went from 0.70 to 0.89 on LoCoMo, with 1.4 to 2.3 notes sent to the agent per question instead of 5.
